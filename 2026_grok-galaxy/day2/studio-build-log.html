開播倒數圖卡：尚未開始三人討論

00:10:03 — 00:12:41

隔夜轉向：快閃活動太重，改做觀眾可以一起玩的遊戲

開場三人自我介紹：Matt、Roshan，以及自稱 Potato、也叫 Lauren 的主持人。他們回顧 Day1 原本要做體驗式快閃活動，已完成帳號設定、討論、一些原型；但來賓與隔夜代理研究指出，舊金山的許可、限制與實體執行工作，比剩下兩天能承擔的多。

轉向不只是因為工程比較容易。他們想讓直播觀眾也能參與，而不是大部分時間都看行政與準備工作。新的方向是遊戲工作室：把大家分享的 Grok Bot 範本變成遊戲角色，讓觀眾一起玩。此時只確定要探索這個方向，尚沒有產品。

今天先用白板把想法講清楚，再進最小可用版本的工程計畫，四場主舞台講座之間持續回來建置。這條主線解釋了為何後面會同時出現遊戲、代理分工、宣傳素材與工作室營運。

00:12:41 — 00:17:15

範本變角色：讓機器人的專長成為遊戲風格

Lauren 解釋 Grok Bot 範本是分享已建立機器人的方式，可帶技能、例行工作與選擇性的通用記憶；她強調不應把私人資料一起分享。遊戲想利用這些既有範本，讓角色不只是隨便取名的卡片。

初始角色有魅力、敏捷、智慧三種數值，再配一個有名字的能力。譬如 Dr. Eggbot 的能力可借用它已有的技能名稱，而底層仍對應其中一個數值；這樣比直接顯示『魅力能力』更有個性。

玩家提供自己的主角範本，生成帶隨機外觀的角色，再搭配另外兩隻機器人組成三人隊。現場用熟悉的範本舉例，討論如何把個人收藏轉成可分享、可對戰的遊戲身份。

00:17:15 — 00:20:00

數值要可重現，但還想留下稀有度驚喜

同一範本重複匯入，最好得到同樣數值，避免每次重新抽樣；角色建立後要能持續存在。初步規則是三種數值共用總額 100，再依範本描述分配：擅長協調人可能魅力較高，串接很多服務則可聯想成敏捷。這些分配方式仍在討論，不是已固定的正式演算法。

白板例子把 70 和 30 用完，才發現第三項會變成零，於是討論最低值；最後談到最小 1、最大 98，三項仍合計 100。這個小修正很重要：限制條件是現場推演出來，不是一開始就完整。

又以動作角色扮演遊戲的掉寶機制提出稀有度：普通、稀有、史詩或傳說可能有不同總額加成。確切級距尚未決定。稀有度增加趣味，隨後也把大家帶到『怎樣賺錢又不付費取勝』的問題。

00:20:00 — 00:23:15

先不要賣勝率：營收要和遊戲公平性分開

主持人先問，遊戲工作室終究要賺錢，但怎樣才不會變成付費就能贏？現場明確不喜歡限回合、隔天再來或花錢買戰力的方式，改談裝飾品、獨特帽子、不同場地，以及利用圖像生成製作個人化物品。這些都是候選商業模式，當時並未實作付款。

接著把遊戲想成可以讓人觀戰、分享對戰連結、事後重播的競技場。若場邊有廣告，就可能用觀眾注意力支持營收，又不改變勝負。最後收斂為先做原型、先讓使用者願意來玩；營收設計等體驗成形再加。

00:23:15 — 00:28:28

收斂最小遊戲循環，也把公司周邊工作列出來

核心構想是讓一隊機器人對上另一隊：角色有數值、能力與名稱，玩家先選隊伍與出場順序，再做輕量配對，讓能力彼此較量。例如魅力對智慧；首次建立角色時也可能用語言模型生成特殊加成。先把這條簡單循環做出來，才逐步增加升級、特殊能力或不同場地。

工作室不只是寫遊戲。Matt 提出首頁、搜尋曝光、廣告與獲客；團隊也談到信箱、電話、從 X 留言接收社群回饋及客服。這裡是把公司的營運工作拆出來，想讓多個 Grok Bot 協助，不表示那些管道此時已接通。

白板上的最小流程是：拿 Grok Bot 範本 → 組隊 → 排陣 → 對戰。配對公平、讓玩家有獲勝感與願意再來的誘因仍待設計。主持人刻意保留一個緊湊起點，而不是一次把所有創意塞進第一版。

01:24:10 — 01:29:35

回到工作室：先用沒有登入、沒有資料庫的原型看手感

回來後改成一人操作、Lauren 在旁協助的工作方式。共用遊戲計畫已放進程式碼庫；Matt 讓自己的工程代理先讀該文件，再用個人的 project planning 規則提出首頁方案。採用現成腳手架，不另外發明技術組合，並補上搜尋標題、描述及分享預覽圖。

代理在這裡反而協助減法：移除登入和候補名單，先做簡單首頁。Lauren 說，現在連遊戲好不好玩都還不知道，先用硬編碼資料和快速原型看視覺與操作，再做真正後端。

工作分成 Grok Bot 裡的對話與調度，以及 Cursor cloud agent 的工程實作。P-Stack 的 potato mode 是本場使用的工程工作流程，不是另一個遊戲模式；雲端代理仍在準備環境，不能把『已派出』寫成『已完成』。

01:29:35 — 01:33:45

美術遊樂場與工程代理：先說清楚職責，再讓它複述

Matt 用 creative director 代理研究視覺方向：參考 Super Auto Pets 的輕鬆圖像，從他熟悉的 Phaser 切入，再研究 DialKit 滑桿能否即時調整 SVG 小角色，做一個素材試驗場。他坦言自己不是遊戲設計師，所以把『幫我理解這個領域』放在製作前。

Lauren 的建議提示是：請 Dr. Eggbot 建立工程代理，使用 P-Stack／potato mode 派出雲端代理，負責調度、監督並檢查成果；現在先專注輕量原型，但不要把角色永久限制成只能做原型，之後還要能做正式工程。

她自己的 chief of staff（掌握全局的協調代理）保有專案背景，再與其他代理合作。Matt 追加『開始工作前，先用自己的話複述』，用來查明長段指令是否被理解。此時 Roshan 說素材試驗場已能在本機開啟，開始接手調滑桿。

01:33:45 — 01:36:45

滑桿不只調美術，也調遊戲常數

素材試驗場跑起來後，三人覺得角色仍太抽象，討論要更像機器人，也注意到顏色可以有規則上的意義。Lauren 提醒先有共同的最小原型，再讓大家往同一份程式加東西，否則素材與玩法各做一套會難以整合。

更重要的想法是把滑桿從外觀延伸到遊戲規則：例如某屬性的 22% 加成，可以一邊調一邊重播，看手感怎麼變。這避免每改一個常數都要再發提示、等代理寫完；主持人與代理都能用這個試驗場檢查結果。

怎樣教評論代理：自己的舊文章與四段結構，比一句「寫自然」更具體

評論標準來自他反覆看生成結果、指出不符合自己風格的地方，而不是另外訓練一個新模型。他也提供自己過去寫的文章，包括大量生成式文字流行前的作品，讓代理理解自己的複句習慣與熱情語氣。像「我想做代理」這種空句，必須追問是什麼代理、做什麼、為什麼。

檢查規則對應四段信：第一段說明應徵角色、為什麼想做與想投入什麼；第二段用一個真實經歷，第三段再用另一個經歷，各自連回職缺；第四段簡短統整，說清楚想為公司帶來的具體影響。不是把所有故事一次堆滿，而是要求每段都有用途。
