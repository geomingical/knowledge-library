Grok Bot for Product Managers

從航空購票漏斗到產品原型：讓資料分析、產品、設計與工程代理接力

本場用航空公司示範環境，從購票數據一路走到需求文件、設計稿與工程派工。重點不是叫一個機器人包辦，而是給不同角色合適的工具、記憶與驗證環境，讓它們交接工作；人仍須辨認數據、決定方向並審查產物。現場也保留了誤讀漏斗後被代理糾正的過程。

議程講者：Kevin Niparko表定台灣時間 05:30–07:00繁體中文公開摘要

適合需要把分析轉成產品改動的產品經理、設計與工程協作者，也適合正在規劃多代理分工與人工審查點的團隊。

重點章節實作與概念操作流程限制原始來源

用語先說清楚：本頁的「代理」是能代人使用工具、執行工作的 AI；「上下文」是它判斷事情時能讀到的背景資料。其他專門用語在下方詞彙區有白話解釋。

先看本場專門用語的白話解釋
attention list
記錄目前實際關注的工作，再與優先事項比對；本場用來說明PM如何檢查注意力分配，而非單純列待辦。
product conversion funnel
產品轉換漏斗，觀察使用者由一個操作階段進到下一階段的情況；本場藉此找出行動購票流程的流失位置。
PRD
產品需求文件。現場由PM Pete在Notion產出，以清楚需求及P0、P1、P2排序，供設計與工程接續工作。
routine
按指定時間執行的例行任務，例如每天六點送圖表；講者也建議沒有重要事項時不要每次都回報。
EPD
工程、產品與設計的協作組合。本場在群聊中聚合不同角色，讓它們能交換背景、需求與設計決定。
cloud agents
由工程代理啟動的雲端執行代理，帶著程式庫副本處理修改；其產物仍可交回工程、QA或經理再驗證。
shared memory pool
讓團隊共同保留資訊的共享記憶池，與各代理自己的記憶並存；本場說明相關選擇策略仍在試驗與調整。
Teach It a Task
代理雲端電腦上的工作流程教學入口，可錄下實際操作供代理學習；本場以複雜Salesforce流程說明用途。

導覽中已配置Notion、Slack、Figma MCP與Gmail，也展示工程群聊與EPD群聊。這些是已備妥的示範環境，不是輸入一句需求就自動取得所有工具權限；本場沒有逐步演示每一項連接器的安裝與授權。
