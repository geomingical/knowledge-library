Grok Bot for Marketing

行銷實作：界定代理職責，再持續給回饋

本場以虛構航空品牌 Xair 示範如何把市場研究、產品定位、網站與廣告工作分給不同代理，再用專案經理協調交接。重點是清楚的職責、持續回饋與有限授權。新的廣告活動並未在現場啟用；成效分析使用的是既有活動資料。

重點章節實作與概念操作流程現場問答限制與來源

用語先說清楚：「代理」是能使用工具、代人執行工作的 AI；「上下文」是它能讀到的背景資料。

先看本場專門用語的白話解釋
Thought partner (思考夥伴)
指使用者透過對話與 AI 討論策略或修改文案，將其作為思考與靈感的輔助工具。
Asynchronous (非同步)
指工作流程不需要人類與 AI 同時在線，機器人可以獨立完成任務並在稍後回報結果。
MCP (模型上下文協定)
一種讓 AI 工具能與外部數據或工具進行標準化溝通的技術。
Landing Page (落地頁面)
使用者點擊廣告或連結後會跳轉到的特定網頁。
Orchestration (編排)
指自動化系統中，協調多個機器人或程序如何協作、交接任務的自動化流程。
Context Switching (情境切換)
指在處理不同任務或資訊之間轉換時，大腦所需重新適應與重新聚焦的過程。
Pull Request (PR)
在程式碼管理中，開發者請求將自己的程式碼變更合併到主程式碼庫的程序。

01 / 機器人團隊的編排與協作

使用者不再是與單一聊天機器人對話，而是建立一群具備不同職能的機器人團隊。透過非同步（Asynchronous）的工作流程，機器人可以在背景平行處理任務，並在不同角色間進行資訊交接。

現場例子

在 Xair 活動中，市場研究員完成競爭對手分析後，將結果交接給產品行銷員，後者根據分析內容撰寫定位簡報，實現跨角色的自動化流轉。

02 / 自主操作電腦的範式轉移

機器人不僅能透過 API 溝通，還擁有自己的電腦與瀏覽器。這讓它們能像真人一樣操作各種數位工具，執行高度客製化的任務，如管理廣告平台或修改網站程式碼。

03 / 降低情境切換成本的專案管理

情境切換（Context Switching）是指在不同任務間轉換時產生的認知負荷。透過設定專案經理機器人作為唯一的聯絡窗口，可以減少人類需要監督多個機器人的壓力。

現場例子

使用者只需與專案經理對話，由其負責向其他專家機器人下令、收集進度並發送截圖，讓使用者能抽離瑣碎細節進行核心決策。

現場問答，補上使用邊界

問題與回應經濃縮，不是逐字引述。

是否有任何領域是你不會允許它們自主執行的？你會建議我完全自動化嗎？

建議將機器人視為隊友，從簡單任務與有限權限開始。隨著你提供更多提示與回饋，讓其符合你的風格，再逐步擴大權限。目標是建立豐富的記憶與上下文，最終處理複雜任務，但務必從小規模且低風險的任務開始。

你認為行銷人員在使用這項技術時最大的障礙是什麼？

最大的障礙是使用者可能不清楚產品實際的能力。如果只是將其當作另一個大型語言模型（LLM）來提問，就無法發揮價值；必須將其視為可以交付任務、處理聯絡人等實際工作的工具。

原片 06:33:59 ↗ 官方回放

如何確保公司的情報不會外洩，或資訊不會被用於模型訓練？

我們提供數據隱私模式，使用者可以選擇加入或退出（opt in or out），以決定是否允許數據用於訓練。對於實際的安全需求，我們有專門團隊根據個案情況進行溝通與處理。

原片 06:40:02 ↗ 官方回放

有沒有辦法將 Grok Bot 連接到 Grok CLI 以及我們在 Grok 網站上的資訊？

你可以讓 Grok Bot 指向你現有的工作，將其視為工作的框架（Harness），這樣就能整合上下文。此外，你可以透過自己的電腦將 Grok Bot 直接與 Grok CLI 連接。
